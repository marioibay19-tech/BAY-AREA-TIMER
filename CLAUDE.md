# Bay Status Board

Customer-facing status screen for the DPWH Equipment Management Division (Regional Office 1) vehicle maintenance bay, like the board in an auto shop waiting area. It shows vehicles currently in the bay with a running timer against a time limit, the mechanics on each job, and a waiting queue. Staff update it from a "Staff" button; every open screen updates live.

The user is not a developer. Explain Firebase and GitHub steps in plain, numbered steps and say exactly where to click.

## Files
- `index.html` is the whole site: HTML, CSS and one `<script type="module">`. There is no build step and no npm.
- `firestore.rules` is for reference only (see Firebase below).
- `README.md` has the setup steps for the user.

## Stack and hosting
- Static site on GitHub Pages (repo `marioibay19-tech/BAY-AREA-TIMER`, branch `main`, root folder). Live URL: https://marioibay19-tech.github.io/BAY-AREA-TIMER/
- Shared live data in Firebase Firestore, project `bid-monitoring-f1308` (the same project the user's bid monitoring site uses). The web config is already filled in at the top of the module script (`FIREBASE_CONFIG`). Firebase web config values are public by design.
- Do NOT edit the project's Firestore rules without asking. They already allow all reads and writes (`match /{document=**}`) and the bid monitoring site depends on them. Anyone with the link can technically write to the database; the staff PIN (below) only keeps customers out of the UI. This was accepted.
- If `apiKey` in `FIREBASE_CONFIG` is empty, the page runs in local demo mode using localStorage and shows a banner.

## Data model (Firestore)
- Collection `entries`, one doc per vehicle on the board, doc id = `String(entry.id)`.
  Fields: `id` (ms timestamp), `plate`, `vno` (property no.), `desc`, `who` (assigned person), `repair` (Preventive / Corrective / Express Maintenance), `status` (`bay`, `wait` or `sched`), `since` (ms timestamp, reset when moved between columns), `limitHrs`, `bay` (text such as "Bay 1"), `mechanics` (array, max 5 names).
  `work` (work description text, shown on the customer board), `dateIn` ('YYYY-MM-DD', date the vehicle entered the bay area; set on add, defaults to today, editable in Staff panel, never reset by dragging). `remarks` (free text such as "Waiting for parts", shown on the customer board under Work, editable in Staff panel). `schedDate` ('YYYY-MM-DD') and `schedTime` ('HH:MM', optional) for `sched` entries; a scheduled entry has `dateIn` '' until it is moved to Waiting/In bay (drag or Edit), which sets `dateIn` to today and resets `since`. Entries without `dateIn` fall back to the date of `id` (or `since` for small demo ids).
- Divisions are per VEHICLE: each `VEHICLES` item has `div` (from the user's list of 2026-11-06; 124 of 127 have one; the same person can have vehicles in different divisions). Fallback for vehicles without `div`: `meta/settings.divisions` = { normalized end-user name: division }, edited in Staff → Settings → "Divisions for other end-users" (`renderDivisions()`, lists only people whose vehicles lack a division). `usualDivision(vno, who)` = vehicle `div` || person fallback; entries store `division` only when it differs from that (typed in the form's Division box); `entryDivision(e)` = `e.division || usualDivision(e.vno, e.who)`. Added vehicles (Settings → Vehicle list) also take a Division. The form's End-user/Division boxes fill in when a vehicle is picked (`fillWhoFromVehicle`). Finished records store the division at the time of Done. Shown via `endUserHtml(e)` (`.enduser`) on cards and rows, in the Finished table, the print slip and the CSV.
- Doc `meta/roster` with `{ names: [...] }`, the mechanics list used by the pickers.
- Doc `meta/settings`: `pinHash` (SHA-256 of `'bay-status-board|' + PIN`; missing = default PIN 1234), `bays` (array, default Bay 1–4), `limits` ({repair type: hours}, defaults Preventive 2, Corrective 4, Express 1). Saved with merge; edited in the Staff panel.
- Entry hold fields: `hold` (reason text, '' = working), `holdAt` (ms the current hold started), `heldMs` (ms already on hold). Worked time = `workedMs(e)` = (holdAt or now) − since − heldMs; the limit, bar, near/over and the finished `bayMs` use worked time. History records also get `holdMs` (total time on hold). Moving lists resets `heldMs`, and so does Edit whenever it changes `since` (status change or new timer start). `heldBefore(e, end)` ignores a stored `heldMs` longer than end − since (leftover from an old restart), so such entries heal themselves. Bug fixed 2026-11-10: Edit used to keep old hold time, freezing the restarted timer at 0m 00s.
- Doc `meta/clock` `{ t: serverTimestamp }`, written/read by each screen to measure its clock offset.
- Collection `history`, one doc per finished job, doc id = `String(entry.id)`: all entry fields plus `doneAt` (ms), `bayMs` (ms in bay = doneAt - since), `overLimit` (bool). Written by the Staff panel "Done" button (in-bay vehicles only) in one batch with deleting the `entries` doc. Read only while the Finished page is open (`subscribeHistory`, ordered by `doneAt` desc). Allowed by the existing `{document=**}` rule, so no rules change was needed.
- `VEHICLES` (127 items: `no`, `plate`, `desc`, `who`, `div`) is embedded in `index.html`. Vehicles added in the Staff panel are stored in `meta/settings.vehicles` (same fields); `rebuildVehicles()` merges them into `ALL_VEHICLES` (an added vehicle with the same property no. replaces the built-in details) and refills the search list. Use `ALL_VEHICLES`/`findVehicle()`, not `VEHICLES`, for lookups. Typos fixed 2026-11-05: Komatsu, Atlas Copco, Allan N. Hufana, Alvin-Barrey L. Taguicana, Julian M. Narvas, Jr. It powers the searchable vehicle field. Plate `N/A` means no plate, so the board shows the property number as the main label. The end-user (`who`) and their division are shown on the customer board (user asked for it 2026-11-06; TV option `who` can hide them).

## Behaviors to preserve
- Board layout: In the bay now (left); Awaiting parts, then Scheduled (right column). The `wait` status is labelled "Awaiting parts" everywhere in the UI (renamed from "Waiting" at the user's request 2026-11-06; data value is still `wait`). Rows in that list don't repeat an "Awaiting parts" hold tag. Waiting rows show only Date in (the waiting timer was removed at the user's request). Scheduled rows are sorted by date/time and labelled Today (amber), Tomorrow, weekday date, or Overdue (red).
- Staff panel has three columns: Scheduled, Waiting, In bay. Each row has an amber "Move to…" dropdown (the other two lists: In bay / Waiting / Scheduled) because dragging was hard and does not work on touch screens; the user asked for a dropdown rather than separate buttons. Choosing Scheduled asks for the date. Dragging still works on computers. Both go through `moveTo()`.
- Vehicles can also be dragged directly on the main board (not in TV mode, mouse only): drop zones `#bayZone`, `#queueZone`, `#schedZone`. While dragging, `boardDragging` pauses the 1-second `renderBoard()` redraw so the dragged card isn't replaced. Moving into Scheduled (board or Staff drag) asks for the date with a prompt (default tomorrow); cancelling leaves the vehicle where it was.
- On hold: Staff row "Put on hold…" dropdown (Awaiting parts / Under observation / At outside shop / Other reason…, or Resume work). Bay cards on hold are blue with the reason tag and "Elapsed (paused)"; waiting rows show the reason tag.
- Pause (can't finish today): In-bay Staff rows have "⏸ Pause" / "▶ Resume". Pause asks which day work continues (default `nextWorkday()`, skipping Sat/Sun) and sets `hold = 'Paused'` (`PAUSED`) plus `pauseUntil` ('YYYY-MM-DD'); it uses the hold timer, so paused time doesn't count. The board tag uses `holdLabel(e)`: "Paused · continues tomorrow / today / Mon, Nov 9". Resume = `resumeJob(e)` (user request 2026-11-11): the timer restarts from 0 for the new day (`since` = now, `heldMs` 0), earlier days' worked time is added to `priorMs`, `workDay` counts up (card footer shows "day 2"), and `overAnyDay` remembers if an earlier day went over the limit. Done records `bayMs` = priorMs + today, `dayMs` = today, `overLimit` = overAnyDay || today > limit; multi-day results read "Within/Over limit · N days". "Resume work" in the hold dropdown on a paused job also uses `resumeJob`. Other hold reasons still use `setHold` (timer continues, no reset). Any other hold reason clears `pauseUntil`.
- Bay is a dropdown from `settings.bays` (old free-text bays are kept as an extra option when editing). Adding/editing into an occupied bay asks for confirmation (`bayFreeOk`).
- Time limit fills in from the repair type's default unless staff typed one (`limitTouched`).
- Work and remarks are cut to 2 lines on the board (`.wtext`); full text in Staff panel, tooltip, and Finished page.
- Elapsed time ticks every second; the card turns red with "OVER LIMIT" past the limit.
- Staff panel has two columns (Waiting, In bay); vehicles are dragged between them. Dragging resets the timer (`since`).
- Every field is editable at any time, including while waiting, via the **Edit** button on each vehicle in the Staff panel (In bay and Waiting). Edit loads the vehicle into the top form (title "Edit …", "Save changes" / "Cancel edit"); it can change the vehicle (duplicate guard applies), repair type, work, remarks, date in, status, bay, mechanics, time limit and the timer start (`fSince`). Changing status without touching the timer start resets `since`, like dragging. The Staff rows show a read-only summary; the old inline editors were replaced.
- Adding a vehicle already on the board (same property no.) is blocked.
- All user-supplied text goes through `esc()` before `innerHTML`, because the data is public and shared.
- The Staff panel is not rebuilt while someone is typing in it (`staffBusy()`), so live updates don't wipe input.
- Shared clock: every screen measures its offset from Firebase's server time (`serverOffset()`, every 30 min) and uses `nowMs()` instead of `Date.now()` for `since`, `doneAt`, timers and the header clock. Use `nowMs()` for any new time logic. `id` still uses `Date.now()` (just a unique id).
- Staff PIN: the Staff button, board drag, Finished-page Undo/Delete and CSV export need the device to be unlocked (`requireUnlock()`, `isUnlocked()`). Unlock is remembered per device in localStorage (`bayBoardUnlock` = current pin hash), so changing the PIN locks every other device. "Lock this device" and "Change staff PIN" are in the Staff panel. The default PIN is not accepted until settings have loaded (`settingsLoaded`). Viewing the board and Finished page needs no PIN. Forgot PIN: delete the `pinHash` field of `meta/settings` in the Firebase console, which resets it to 1234.
- Connection status under the clock (Live / Connecting / Offline) from snapshot metadata (`includeMetadataChanges`); a red offline bar shows after 8 s offline, with the last update time.

## TV display mode

- Red alert bar lists over-limit vehicles. Chime plays once per vehicle when it newly crosses the limit, not for vehicles already over when the page loads (`alerted` set).
- "N MIN LEFT" amber badge within `NEAR_MS` (15 min) of the limit; this shows in normal mode too.
- No scrolling on the TV: `body.tv` is exactly the screen height and each list (`#bayGrid`, `#queueList`, `#schedList`) shows only what fits. `paginate()` groups items into rows and rows into pages after every `renderBoard()`; pages flip every 15 s (`tvPageTick`), with "Page 1 of 3" and dots in the section title. (The old auto-scroll was removed.)
- Day/Night colors: `applyTheme()` sets `data-theme` (`light`/`dark`) on `<html>`. Staff screens: "◐ Auto / ☀ Day / ☾ Night" button under the clock, per device in localStorage `bayBoardTheme` (default `auto`). TV: `meta/settings.tv.theme` chosen in Staff panel → TV display (default `dark`). `auto` = Day 6 AM–6 PM (`DAY_START`/`DAY_END`), re-checked every minute. Day colors use slightly darker amber/blue/red for contrast on white.
- Header counts (`#counts`, all modes): in the bay · waiting · on hold (if any) · scheduled today.
- TV display options in the Staff panel (`meta/settings.tv`, key=false hides it, TV only): mechanic names (`.mechanic-block`), property no. (`.pno`), make & model (`.vd`, waiting/scheduled `.vdesc`), work (`.w-work`), remarks (`.w-rem`), date in (`.datein-row`, `.qrow .datein`). Body classes `tvh-<key>`.

## Interactive 3D view (added 2026-11-13)
- `#3d` in the URL (or the "Interactive" nav button, `#isoToggle`) toggles `body.show-iso`, which hides `.layout`/`.alert-bar` and shows `#isoPage`. Handled in `showPage()`; hidden in TV mode (`setTV()` now calls `showPage()`). Leaving and re-entering clears the scene so the drop-in animation replays.
- Pure CSS 3D, no library: `#isoWorld` gets `translate(-50%,-50%) translate(pan) scale(fit*zoom) rotateX(tilt) rotateZ(rz)` from `isoCamera()` (fits the floor into `#isoStage`). Boxes come from `isoBox(cls,w,d,h,x,y,z)`, which makes a cuboid of five faces with tones from `--vc`/`--base` via `color-mix`. Do not put `opacity` on preserve-3d elements, because it flattens them.
- `isoLayout()`: the bay zone has one slot per `bayNames()` entry, plus "No bay set" slots for bay vehicles without a free named bay. Awaiting parts and Scheduled lots (2 columns, at least 4 slots) sit side by side underneath. The floor is rebuilt only when the layout `key` changes. `renderIso()` runs at the end of every `renderBoard()` (1 s), and keeps one element per entry in `ISO.els`. A position change slides the vehicle (CSS transition) and adds a hop. Removed entries lift away.
- Vehicle shape: `isoKind(e)` reads `desc` (pickup / suv / van / truck / heavy / small). `ISO_MODELS` returns HTML. Cars are 3D drawings (user request 2026-11-13): `isoExtrude(profile, w, win)` extrudes a side profile ([y, z, edgeType], front = −y; edge types '' body, 'g' glass, 'b' open bed, 'f' headlights, 'r' taillights) into panels placed with exact `matrix3d` by `isoFace()` and shaded by `isoShade()` (fixed light `ISO_LIGHT`). Side panels use the profile as `clip-path` with window polygons inside. `isoWheelsHtml()` draws round wheel and tire discs. The truck is a cab profile plus a cargo box. Machines and small equipment are detailed models too (user request 2026-11-13): excavator (`isoTrack()` crawler tracks, turning house, cab, `ISO_BOOM` outline for boom, arm and bucket), dozer (blade, hood, cab), loader and backhoe (`isoLoader()`: big wheels, frame, cab, lift arms, bucket, plus the rear arm on backhoes), genset (vented enclosure on a skid), chainsaw, and floodlight trailer (mast and lamp head). `isoExtrude` opts: `closed` draws all edges (closed outlines must run clockwise in y/z, so the normals point outward); `edge`/`side` take shade → style functions; edge type 'k' = dark steel. `isoSub(x,y,z,html)` places a part. `isoKind` maps desc → chainsaw / floodlight / genset / excavator / dozer / backhoe / loader / truck / van / suv / pickup. Color class from `isoState()`: work/near amber, over red, hold blue, wait grey, sched green (late red). Tags (`.iso-tag`) counter-rotate with `--rz`/`--tilt` and counter-scale with `--inv`, so they face the camera at a constant size (smaller on small stages).
- Drag: pointer events on `#isoStage`. Dragging a vehicle shows `.iso-ghost`, and the target is found with `document.elementsFromPoint` on `[data-zone]` (slots carry `data-bay`). `isoDrop()` asks `requireUnlock()`, sets `e.bay` for a named bay (`bayFreeOk`), and otherwise calls `moveTo()`. Dropping on the bay zone (not a slot) keeps the vehicle's bay if free, else the first free bay. Dragging the floor turns and tilts (Shift or middle button pans; on touch it pans when zoomed in). Wheel zooms.
- Workshop look (user sent an isometric garage picture, 2026-11-13: "like that, specially when they are in the Bay"): a light blue-grey floor; `isoWalls()` builds 4 walls with windows and a pegboard on the inside face (`.fs`), and `isoCamera()` hides the 2 walls between the camera and the floor (class `near`). `isoLift()` puts an orange two-post lift, a blue beam and floor runners in each named bay. Cars and vans (`ISO_LIFTABLE`) in a named bay rise on the lift (`.raised`) while working/near/over and come down on hold; the lift arms are model parts shown only `.inbay`. `isoCrew()` draws one mechanic per assigned mechanic (max 2) beside working bay vehicles. They walk a loop around the vehicle (`ISO_WALK` builds the `isoPath`/`isoLegL`/`isoLegR` keyframes once from a plan of walk/turn/stand steps, stopping at the front, sides and back facing the vehicle; the 2nd mechanic is half a lap behind via `--md`). `isoProps()` adds a cabinet, workbench, tool chest, tires and a pallet in the east strip (`ISO_PAD.r`). Bay tags are kept short (plate + timer) so neighbours don't overlap.
- Performance (user reported lag, 2026-11-13): never put CSS variables on `#isoWorld` or rewrite unchanged classes on vehicles, because either restyles every face (~1,400 elements). `isoCamera()` sets only the world transform plus each tag's transform (`ISO.tagT`), and caches the stage size during turning (`isoCamera(true)` via `isoCameraSoon()`, once per frame). Animations use transform/opacity only (glow ring = `.iso-shadow::after` scale+opacity, roof light = face opacity). Measured with CDP Performance metrics: turning style time went 654 ms → 130 ms per 60 moves, idle 35 → 8 ms per 5 s.
- Added 2026-11-13 ("add everything in the 3D interactive view"):
  - TV: Staff → Settings → TV display → "TV shows" (`meta/settings.tv.view3d`, `tv3d()`); `?tv#3d` also works. `showPage()` shows the 3D view in TV when either is set (and `applySettings()` calls `showPage()`). In TV, the tools, hint and details are hidden, the alert bar stays, pointer input is ignored, and `isoTvSway()` (rAF, ~30 fps) sways `rz` ±16° around the start angle every 40 s.
  - Drive in / out: `isoLayout()` returns `lane` (a driveway between the two lots, the aisle in front of the bays, and the off-floor point). New vehicles (after the first paint) use `isoPathIn()`; removed ones get `.leaving`, come off the lift (1.5 s), then `isoPathOut()`. `isoDrive()` runs matching Web Animations: translate on the element, rotateZ on `.iso-hop` (the shadow is inside the hop, so it turns too). `isoStopDrive()` cancels it if the vehicle comes back. The floor has a painted `.iso-lane` "IN · OUT".
  - Warnings: an "OVER LIMIT" banner (`.t-alert`, blinking) inside over-limit bay tags, and a red roof light. Parts boxes (`.iso-kit .kit-parts`) show beside `wait`-state vehicles.
  - Repair type, on working bay vehicles: `rt-pm` (Preventive and Express) opens the hood (`isoHood()`: engine bay plus a lid swung up at 62°, cars only). `rt-cm` (Corrective) hides the front-left wheel (`.cf.fl`, made by `isoWheelsHtml`), shows the brake hub (`.cf.hub`), and puts the tire on the floor by the lift post (`.kit-tire`).
  - Simple view button (`#isoLite`, localStorage `bayIsoLite`, `body.iso-lite`): hides walls, props (`.iso-props`), shadows and floor runners, and stops the mechanics', roof-light and drop-in animations.
- Details panel `#isoInfo` (click a vehicle): fields, a "Move to…" select (`isoDrop`) and Edit (opens the Staff panel with `startEdit`). It is not redrawn while its select has focus.

## Finished maintenance page
- `#finished` in the URL (or the "Finished" button) shows the page instead of the board; "Back to board" clears the hash. Hidden in TV mode.
- Filters: text search, finished from/to date, repair type. Summary line counts jobs, within/over limit, average time in bay.
- Per row: Print (opens a one-page job record with signature lines: Mechanic / Inspected by / Received by), Undo (puts it back in the bay with its original `since`, blocked if the vehicle is already on the board) and Delete.
- Soft delete: Delete sets `deletedAt` on the history doc instead of deleting it. "Recently deleted" (`showBin`) lists those with Restore; records deleted more than 30 days ago are removed for good when the Finished page loads (`purgeOldDeleted`). Staff-panel Remove also goes to the bin: the entry is written to `history` with `deletedAt` and `removedFromBoard: true` (restore puts it back on the board).
- Summary (collapsible, follows the filters): by month (jobs, PM/CM/Express, % within limit, average time) and by mechanic.
- Vehicle history: "History" button on each Staff row, and clicking a vehicle on the Finished page, filter the list to that vehicle's property no. (or plate).
- "Export to Excel (CSV)" downloads the filtered list (UTF-8 BOM so Excel reads it). The CSV includes the end-user; the on-screen table does not.
- "Remove" in the Staff panel is for mistakes (goes to Recently deleted, not the finished list); "Done" is the normal way to finish a job.
- Never name a module variable `history` — it would hide `window.history`, which TV mode uses.
